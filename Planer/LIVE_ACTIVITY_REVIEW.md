# Planer: Live Activities и развитие интерфейса

Проверено 8 сентября 2026. Основа: `733b911`, последняя успешная сборка ветки `agent/ios-family-offline-credit`. Исправления: версия 1.4.1 (15), ветка `codex/live-activity-repair`.

## Что обнаружено в коде

- Менеджер выбирал карточку только по дню, не проверяя `activityState`, и после `update` безусловно показывал «Працює». Завершённая карточка не может снова стать активной от обновления. Теперь повторно используются только `.active` и `.stale`, а состояние отслеживается через `activityStateUpdates`.
- `@MainActor` не предотвращал пересечение двух запусков: методы `update` и `end` освобождают actor на время ожидания. Теперь запросы выполняются последовательно.
- Перед проверкой foreground удалялись существующие карточки. Проверка перенесена перед удалением и повторяется после ожидания.
- При смене дня без изменения сумм SwiftUI не запускал обновление. Добавлена проверка смены дня, работающая только пока приложение активно.
- Отложенный запуск при активации был отдельным `Task`, не связанным с жизненным циклом экрана. Теперь используется отменяемая `.task(id: scenePhase)`.
- Настройки без доказательств объявляли причиной пустой капсулы регистрацию расширения после подписи. Этот текст заменён фактическим состоянием и пояснением ограничений.
- Полные большие суммы могли не помещаться в компактный Dynamic Island. Добавлены компактный числовой формат, одна строка, масштабирование и полная сумма для VoiceOver. На экране блокировки видно время обновления.

Эти дефекты подтверждены чтением кода. Точная причина отсутствия карточки на конкретном iPhone без проверки установленного приложения и системного журнала не установлена. Успешная сборка не доказывает корректность повторной подписи IPA и регистрацию WidgetKit на устройстве.

## Ограничения текущей реализации

Одна Live Activity живёт до восьми часов; после завершения она может оставаться на экране блокировки ещё до четырёх часов. Это не постоянный виджет. Источник: [Apple — Displaying live data with Live Activities](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities).

Запуск выполняется локально, `pushType: nil`. Для изменения карточки после изменений на другом устройстве сейчас нужно открыть Planer и синхронизироваться. Серверная доставка обычных уведомлений сама по себе не обновляет Live Activity. Для этого нужна отдельная реализация ActivityKit push: регистрация токенов, хранение на сервере, APNs, завершение и очистка токенов.

IPA из существующего workflow не подписан. При установке необходимо сохранить и подписать `PlugIns/PlanerLiveActivity.appex` вместе с приложением. Проверка файлов при упаковке не проверяет подпись после стороннего установщика.

## Проверка на iPhone после установки

1. Открыть Planer, войти в аккаунт и дождаться синхронизации.
2. Открыть «Налаштування → Dynamic Island і екран блокування». Если iOS запрещает Live Activities, включить разрешение в настройках приложения.
3. Нажать «Запустити повторно», свернуть приложение, проверить капсулу на поддерживаемом iPhone и заблокировать экран.
4. Добавить расход, снова заблокировать экран: проверить сумму и время обновления.
5. Проверить большую сумму и смену основной валюты. Удалить карточку вручную: статус не должен продолжать показывать «Працює».
6. Повторить после окончания восьмичасовой сессии и после смены дня. Открытие Planer должно создавать актуальную карточку.
7. При отсутствии отображения сохранить текст ошибки из настроек и проверить присутствие расширения после подписи. Не считать одну только надпись «Працює» доказательством отображения.

## Предложения по функциям

| Приоритет | Дополнение | Польза и объём |
| --- | --- | --- |
| 1 | Постоянный WidgetKit-виджет бюджета | Остаток бюджета и быстрый переход в приложение без обещания вечной Live Activity. Нужны App Group, общий снимок и timeline. |
| 1 | Скрытие сумм на экране блокировки | Пользователь выбирает, показывать суммы или только факт обновления. Настройка должна применяться и к уже запущенной карточке. |
| 2 | App Intents / Shortcuts для добавления расходов | Быстрый ввод с Siri и системных действий. Нужны выбор кошелька, категории, проверка суммы и понятный результат. |
| 2 | Импорт и экспорт CSV | Перенос истории и резервная копия. Нужны предпросмотр импорта, сопоставление колонок и защита от дубликатов. |
| 3 | ActivityKit push для семейного бюджета | Обновление карточки без открытия Planer. Отдельный серверный проект с APNs и проверкой прав доступа к семейному пространству. |

Кредиты, семейные пространства, офлайн-очередь и уведомления уже есть в основе; повторно добавлять их как «новые» функции не нужно.

## Направление дизайна

Главный экран сейчас последовательно показывает шапку, карусель кошельков, бюджет и операции; снизу находятся три быстрых действия. Предлагаю повысить заметность остатка бюджета, оставив выбор кошелька вторым уровнем:

- Наверху — переключатель личного/семейного пространства и настройки.
- Одна спокойная карточка: общий баланс, остаток бюджета и тонкая шкала расходования.
- Основное действие — «Додати витрату». Доход и перевод доступны в форме выбора типа операции.
- Ниже — сегодняшние операции и ближайший платёж из уже существующих данных.
- Один основной акцент, нейтральные поверхности, красный только для расходов/ошибок, зелёный для доходов. Стекло оставить для системных панелей и плавающих действий, не распространять его на все строки.
- Сохранить текущие четыре раздела. Проверять крупный размер текста, VoiceOver, контраст и светлую тему.

Интерактивный концепт в ответе использует демонстрационные данные. В IPA включены изменения карточки Live Activity и настроек; предложенный главный экран пока является вариантом для обсуждения.
